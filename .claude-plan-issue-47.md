# Implementation Plan — Issue #47

**Foods page: edit does nothing, and delete removes items without confirmation**

## Findings

- **Edit "does nothing":** The wiring is correct (`startEdit` at `src/FoodsPage.tsx:151` sets `editing` + `setForm(formFrom(food))`; unit test `src/FoodsPage.test.tsx:165` passes). The real problem is **visibility** — the Add/Edit form is in the right `<aside>` (`src/FoodsPage.tsx:297`), which sits below the whole food list on mobile and may be off-screen on desktop. The form populates but the user can't see it. Fix: scroll the form into view and focus the name field on edit.
- **Delete with no confirmation:** `src/FoodsPage.tsx:281-288` calls `deleteFood` directly. Match the app's pattern in `src/MealSection.tsx:21-23` (`window.confirm(\`Delete "${...}"?\`)`). The category delete on the same page already confirms (`src/FoodsPage.tsx:206`).
- **jsdom note:** `scrollIntoView` is unimplemented in jsdom — add a stub in `src/vitest.setup.ts`. Focus is testable via `toHaveFocus()`.

## Branch
`fix/foods-page-edit-visibility-and-delete-confirm`
